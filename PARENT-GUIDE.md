# Parent guide

Your code makes the magic possible; your kid should feel like the inventor. Prepare before each session so the 30 minutes go to play, not debugging.

## Before each session (10 min)

1. Read the week's README and gather materials.
2. Flash the code once and test it.
3. Pick the **knobs** (numbers at the top of the file) your kid will change.

## How much to hand over

| Weeks | Kid does | You do |
| --- | --- | --- |
| 1–10 | Connects clips, tests, decorates, races | Batteries, motors, hot glue |
| 11–20 | Chooses icons and numbers in Blocks, presses Download | Writes and pastes code |
| 21–30 | Changes speeds and times, plans routes with arrows | Builds the program skeleton |
| 31–40 | Drags one or two blocks per session | Combines sensors, debugs |
| 41–50 | Trains AI models alone, writes robot lines and stories | Connects the model to the robot |

## Using your coding skills

- **Write in TypeScript, show in Blocks.** MakeCode converts both ways as long as you stick to simple statements. Avoid classes and complex generics in files the kid will see.
- **Make knobs obvious.** Put tunable numbers at the top with a comment.
- **Version control:** commit after each session. Your kid's changes in `main.ts` are a nice history of their learning.
- **Simulator:** the MakeCode simulator is great for trying ideas at the table before driving the robot.

## Using AI as a parent tool

- Generate printable mazes, treasure maps, coding arrow cards and robot coloring pages.
- Ask an AI to write a 5-scene story for week 47 with one robot action per scene.
- Ask an AI to explain or extend the MakeCode programs here, or port them to another car kit.
- At 6, AI is your tool, not their chat partner. You type and filter; turn answers into something physical.

## When things go wrong

Say "great, we found a bug!" and fix it together. Check in this order: batteries, connections, the right program flashed, then the code.
